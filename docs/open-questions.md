# 確認事項の統合と決着

4つの実装指示書に散っていた確認事項 48件を突き合わせた。重複を統合し、こちらで決められるものは決めた。

| 区分 | 件数 | 意味 |
|---|---|---|
| こちらで決着させた | 23 | 回答を待たない。下記 §2 の決定が正である |
| 田中氏の回答を要する | 25 | ただし全件に「確定するまでの扱い」を定めた（§3） |
| **Codex の着手を止めるもの** | **0** | 実装は今から始められる |
| 公開を止めるもの | 3 | 営業日と営業時間、Googleビジネスプロフィールとの一致、ドメインの向き先 |

---

## 1｜Codex への結論

**着手を止める項目は無い。** §3 の25件はすべて、確定するまでの表示のしかたが決まっている。
未確定の欄を推測で埋めることも、空欄のまま出すことも起きない。

公開の直前に、下記3件だけを確認する。

1. **営業日と営業時間**（Q1）。誤った営業時間は来店客の不利益に直結する。確定するまで構造化データから `openingHoursSpecification` ごと省く
2. **Googleビジネスプロフィールの登録名・住所・電話**（Q22）。サイトと1字も違わないこと
3. **ドメインの向き先**（Q24）。`www.tanakauo.com` を新サイトに向けるか、別のパスで出すか

この3件以外は、後から足せる。**足すことを前提に、欄だけ先に作らない。**
確定していない項目は、欄ごと出さないのが本設計の方針である（§3 参照）。

## 2｜こちらで決着させた項目

回答を待たずに確定させた。理由を付す。**この決定を覆すのは田中氏だけである。**

### 2-1｜設計方針として既に決まっていたもの

| # | 項目 | 決定 | 理由 |

| D5 | 業務用卸の問い合わせ | **商品ページの同じ導線に集約** | 別ページを作らない。問い合わせの入口は1つに統一する（SEO手順書 §3） |

### 2-5｜WordPress と SWELL

SWELL 側の設定に依存しない書き方を採る。これにより、管理画面を開く前に決めるべきことが無くなる。

| # | 項目 | 決定 | 理由 |
|---|---|---|---|
| D15 | SWELL のフォント設定 | **設定に触らない。追加CSSで上書きする** | `body` と見出しに指示書 §2 の `font-family` を、SWELL の指定より高い詳細度で当てる。設定項目の所在を探さなくてよい |
| D16 | Google Fonts の読み込み | **切れるなら切る。切れなくても実装は成立する** | 読み込みが残っても `font-family` の指定が勝つ。速度の問題であって、表示崩れの問題ではない |
| D17 | ヘッダーロゴ | **画像を上げない。サイトタイトルをテキストで出しCSSで整える** | 背景を焼き込んだ画像は明暗どちらの地でも破綻する（指示書 §0） |
| D18 | ページタイトルの二重表示 | **CSSで隠す** | 設定項目を探すより確実。`h1` は本文側で1つだけ出す |
| D19 | ACF などのプラグイン | **使わない** | D20 の決定により不要になった |
| D20 | 「今日の記録」の実装 | **案B（投稿＋カテゴリー）で始める** | 案A（カスタム投稿タイプ）はプラグインに依存する。案Bなら依存が無く、後から案Aへ移せる。**続くことを最優先する** |
| D21 | 子テーマ | **作らない** | 追加CSSとカスタムHTMLで完結する。`functions.php` を触る必要が出た時点で入れる |
| D22 | 有明海の映像の変換 | **変換しない** | 9.5MB のまま使う。モバイルでは映像を出さず静止画にする（移植手順書 §6）。変換の環境が無い |

## 5｜この文書の更新

回答が来たら、この文書の §3 の該当行を §2 へ移し、決定として書き直す。
**同時に、元の指示書の該当箇所も直す。** 2箇所に別のことが書かれる状態を作らない。

回答が来ていない項目を、時間の経過で「たぶんこうだろう」に変えない。
書かないまま公開したページは直せる。誤った情報を載せたページは、直しても信用が戻らない。
