# SEO・構造化データ・週次運用

田中雄一郎が一人で回せることを最優先に設計する。凝った施策は入れない。続くことだけを書く。

文体・禁止事項は `docs/codex-implementation-brief.md` §1 に従う。

## 1｜構造化データ

トップページの `<head>` に JSON-LD を1つ置く。浜焼き・BBQを店頭で提供するため、`Restaurant`（`LocalBusiness` のサブタイプ）ではなく、物販が主で飲食も併設という実態に合わせて `LocalBusiness` を主とし、`servesCuisine` は使わない。

```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "LocalBusiness",
  "@id": "https://www.tanakauo.com/#shop",
  "name": "TANAKA UO",
  "alternateName": "タナカウオ",
  "description": "福岡県柳川市の魚屋。魚の選定、加工、販売、発信を一貫して行う。店頭では炭火の浜焼き・BBQも提供しています。",
  "url": "https://www.tanakauo.com/",
  "telephone": "+81-80-9249-3107",
  "email": "tanakauojapan@gmail.com",
  "founder": {
    "@type": "Person",
    "name": "田中 雄一郎",
    "jobTitle": "目利き"
  },
  "address": {
    "@type": "PostalAddress",
    "postalCode": "839-0254",
    "addressRegion": "福岡県",
    "addressLocality": "柳川市",
    "addressCountry": "JP"
  },
  "sameAs": [
    "https://www.instagram.com/tanakauojapan/"
  ],
  "openingHoursSpecification": [
    {
      "@type": "OpeningHoursSpecification",
      "dayOfWeek": ["Friday", "Saturday", "Sunday"],
      "opens": "08:00",
      "closes": "15:00"
    }
  ]
}
</script>
```

### 埋める前に確認すること

| 項目 | 状況 |
|---|---|
| 営業日 | **確定（2026-08-13）。金・土・日の3日間。** 月曜から木曜は仕入れと加工にあて、店頭には立たない |
| 営業時間 | **確定。8:00 - 15:00** |
| 予約注文 | **受ける。** 締切と単位は未確定のため書かない（`docs/open-questions.md` Q4） |
| `priceRange` | **出さない**（同 D7） |
| 店舗名の表記 | **`name` は「TANAKA UO」単独、`alternateName` は「タナカウオ」**（同 D11） |
| 緯度経度 | Googleビジネスプロフィールに登録済みの座標があればそれに合わせる（同 Q22） |

旧トップページの「9:00-18:00 水曜定休」は**破棄する。** 設計原本の日程層が正しい。

本文の書き方。**この3行が正である。**

```
店頭は金・土・日。朝8時から15時まで。
月曜から木曜は、仕入れと加工にあてています。店頭には立ちません。
ご予約でのご注文を承ります。
```

**「定休日」という語を使わない。** 休んでいるのではなく、仕入れと加工にあてている。
週の半分を仕入れと加工にあてていることは、隠す情報ではなく、この店がなぜ良い魚を持っているかの説明そのものである。

サイト本文・構造化データ・Googleビジネスプロフィールの**3箇所で完全に一致させる。** 1箇所だけ直さない。

**`streetAddress` を入れていないのは意図的である。** 事業計画書に 883-1（事業所）と 884（対面営業場所）の2つがあり、
客が実際に行くのは 884 のほうである。番地が確定するまで `streetAddress` を書かない（`docs/open-questions.md` Q26）。
市までは確実なので残す。**誤った番地は、番地が無いことより悪い。** 地図アプリが別の建物を指す。

浜焼き・BBQページを作ったら、そのページに `Menu` や `Offer` を足すかは、価格が確定してから判断する。価格未確定のまま構造化データに載せない。

## 2｜title と meta description

30文字前後の title、110〜120文字の description を目安にする。キーワードを詰め込まない。読んで意味の通る日本語にする。

### トップ

```
title       TANAKA UO｜目利き 田中雄一郎（福岡・柳川の魚屋）
description 福岡県柳川市の魚屋 TANAKA UO。魚の選定、加工、販売、発信を一貫して行う目利き 田中雄一郎が、有明海と九州各地の漁港、仲卸、漁師をつないで、その日いちばん良い魚を届けます。
```

### 浜焼き・BBQ

```
title       浜焼き・BBQ｜TANAKA UO（福岡・柳川）
description 店先の炭で、その日仕入れた魚をそのまま焼きます。柳川の道沿い、屋根の下の席で。仕入れの内容はその日次第です。魚屋がやっている浜焼きです。
```

### 商品・メニュー

```
title       商品・ご予約｜TANAKA UO（福岡・柳川）
description 鮮魚、干物、急速凍結の加工品、お任せセット。ご自宅用から贈り物、店の仕入れまで。用途とご予算をうかがってから中身を決めます。柳川の店先でお渡ししています。

※ 発送には触れていない。これは暫定ではなく**確定した扱い**である。
　 発送の範囲が確定するまで、`description` にも本文にも発送を書かない。
　 「全国発送」と断定しないこと。詳細は `docs/open-questions.md` Q17。
```

### お問い合わせ

```
title       ご予約・お問い合わせ｜TANAKA UO（福岡・柳川）
description ご予約、贈り物のご相談、店舗への卸、目利きの指導について。メール、Instagram、LINE、お電話で承ります。福岡県柳川市の魚屋 TANAKA UO。

※ 番地を書いていないのは意図的（open-questions.md Q26）。確定したら足す。
```

## 3｜見出し構造と内部リンク

### 見出し

- `h1` は1ページに1つ。トップは「今日の気分で、遊びにおいで。」
- `h2` はセクション見出し。「今日の記録」「食は、職が支えている。」「魚の仕事」「漁港と、仲卸と、漁師と。」
- `h3` はその下位。「選定」「加工」「販売」「発信」、職の連なりの「海で」「市場で」「店で」「その先で」
- 見出しの上に小さな英字ラベルを置かない（実装指示書 §1-4）
- 見出しを飛ばさない。`h2` の次に `h4` は使わない

### 内部リンク

数を絞る。押す理由のある場所にだけ置く。

| 置き場所 | 行き先 | 文言 |
|---|---|---|
| トップ 見出し部 | お問い合わせ | ご予約・お問い合わせ |
| トップ「販売」 | 商品・メニュー | 商品を見る |
| トップ「販売」 | 浜焼き・BBQ | 浜焼き・BBQについて |
| トップ「発信」 | Instagram | Instagram @tanakauojapan |
| 浜焼き・BBQ 末尾 | お問い合わせ | ご予約・お問い合わせ |
| 商品 末尾 | お問い合わせ | ご予約・お問い合わせ |

同じ意図のボタンを1ページに2つ置かない。「ご予約」「お問い合わせ」「ご相談」を混在させず、**「ご予約・お問い合わせ」の1種類に統一**する。

## 4｜Googleビジネスプロフィールとの連動

来店の入口は検索よりも地図側が大きい。サイトとビジネスプロフィールで別々のことを言わない。

**週に1回、同じテーマを2箇所に流す。**

1. サイトの「今日の記録」に書いた内容から、その週いちばん良かった一件を選ぶ
2. ビジネスプロフィールに投稿する（写真1枚＋3〜4行）
3. 同じ写真と同じ趣旨をサイトのお知らせにも載せる
4. 投稿にサイトのリンクを付ける

**常に最新にしておくもの**

- 営業時間、臨時休業（休む日が決まったらその場で入れる）
- 写真（月1回、その月に撮った実写を数枚足す。使い回しをしない）
- 電話番号、住所（サイトと1字も違わないこと。表記ゆれが評価を下げる）

口コミには返信する。短くてよい。定型文を貼らない。

## 5｜週次の運用手順

**毎週1回、まとめて40分。木曜に置く。**

木曜は店頭に立つ金曜の前日であり、仕入れと加工の最終日である。ここで書けば、書いた内容が翌日から効く。
月曜に書くと、木曜までの仕入れを反映できないまま週末を迎える。**木曜以外に動かさない。**

| 順 | やること | 目安 |
|---|---|---|
| 1 | 商品ページの「今週の魚」ブロックを書き替える。触るのはここ1箇所だけ | 10分 |
| 2 | 今週休むものがあれば書く。誤表示は信用を直接削るので、ここを最優先にする | 10分 |
| 3 | お知らせを1本書く。3〜4行でよい | 5分 |
| 4 | 同じ内容をGoogleビジネスプロフィールに投稿する | 5分 |
| 5 | 営業時間・臨時休業が翌週分まで正しいか確認する | 5分 |
| 6 | 季節の告知（お盆、年末、贈答期）が必要なら先に出す | 5分 |

※ 商品ページは価格を持たない設計のため、価格改定の作業は発生しない。
　 詳細は `docs/codex-brief-products.md` を参照。

**やらないこと**

- 記事を量産しない。書くことがない週は書かない
- キーワードを狙った記事を書かない。書けるのは現場の話だけで、それがいちばん強い
- 更新のための更新をしない

## 6｜「今日の記録」の運用

これはこの店にしか書けない。他店が真似できず、検索でも効く。**続けることだけを考える。**

### 書く項目

```
日付        2026年8月13日（木）
七十二候     寒蝉鳴（ひぐらしなく）
潮          中潮
行った市場   柳川
今日の判断   仕入れました／仕入れませんでした
理由        1〜2文
```

### 続けるための設計

- **1分で書き終わる形にする。** 5項目のうち4項目は選ぶだけ。文章を書くのは理由の1〜2文だけ
- 市場から戻った車の中、スマホで書く。パソコンを開かせない
- 毎日書けなくてよい。**書かなかった日を埋めない。** 空白も記録である
- 「仕入れませんでした」の日ほど価値がある。理由が書ければそれが一番読まれる

### 実装側の要件

実装指示書 §4-3 の書式に従う。編集画面は、日付と5項目だけが並ぶ最小の入力にする。装飾機能を出さない。詳細は `docs/wordpress-swell-migration.md` の実装案を参照。

## 7｜計測

**見るもの（月1回、10分）**

| 指標 | 見る理由 |
|---|---|
| ご予約・お問い合わせの件数 | サイトが仕事につながったか |
| 「今日の記録」の閲覧数 | 記録が読まれているか。続ける根拠になる |
| Googleビジネスプロフィールの「ルート検索」「電話」 | 来店に直結する行動 |
| 検索で使われた語 | 客が何と呼んで探しているか |

**見ないもの**

- ページビューの総数。増えても仕事が増えるとは限らない
- 直帰率、滞在時間。読んで納得して帰る人を悪い数字として扱ってしまう
- 順位計測。日々動くものを毎日見ると判断が濁る

**売上だけを見ない。** 設計原本の計測方針どおり、営業利益／営業日、粗利額／労働時間と合わせて見る。サイトはその一部でしかない。

数字が悪い月に施策を足さない。まず「今日の記録」が続いているかを見る。続いていないなら、施策ではなく形を軽くする。

## 8｜公開前の確認

```
1. 電話番号・メールが、サイト／構造化データ／Googleビジネスプロフィールで完全に一致
1b. 番地がどこにも出ていない（Q26 が未確定のあいだ）。市までの表記は可
2. 営業時間が確定し、3箇所すべてで一致（未確定なら構造化データから省く）
3. title と description が全ページ固有
4. h1 が各ページ1つ
5. 同じ意図のCTAが1ページに重複していない
6. 構造化データが Google のリッチリザルトテストを通る
7. 画像すべてに alt がある
8. 404 と、モバイルでの表示を実機で確認
```
