# WordPress + SWELL 移植手順書

静的HTMLで固めた仕様と原稿を、SWELL テーマに載せ替える手順。
配色・書体・禁止事項の正は `docs/codex-implementation-brief.md` であり、**移植後もそれが守られていることが完了条件**である。

## 本書の確度について

SWELL は有償テーマで、設定項目の名称と位置はバージョンで変わる。本書では次のように書き分ける。

- **確度が高いもの** ... WordPress 標準の仕組み、CSS、HTML。断定して書く
- **要確認** と付したもの ... SWELL 固有の設定項目。実際の管理画面で名称と位置を確かめてから進めること。**推測で進めない**

SWELL の機能名を憶測で書かない方針のため、設定項目は「何を実現したいか」を主に書き、SWELL 側の該当箇所は現物で対応づける。

---

## 1｜方針

**SWELL の見た目を活かさない。** SWELL は装飾の既定値が強く、そのまま使うと指示書 §1 の禁止事項に抵触する（角丸カード、セクションの装飾見出し、アクセントバー）。

したがって次の方針を取る。

1. SWELL のデザイン機能は**極力使わない**。使うのは投稿管理・メディア管理・カスタム投稿タイプといった土台の部分
2. 見た目は**追加CSSで指示書のトークンを上書きして作る**
3. トップページは固定ページ1枚に、指示書どおりのHTMLを流し込む。SWELL のブロックパーツで組み直さない

この方針は、SWELL の利点（更新のしやすさ）を残しつつ、既定の装飾に引きずられないための割り切りである。

## 2｜配色と書体の適用

### 2-1 追加CSS（そのまま貼る）

SWELL の設定で色を作らず、**CSSカスタムプロパティで上書きする**。SWELL がどんな既定色を持っていても、この定義が後から効く。

```css
:root{
  --paper:#e8e2d4;
  --ink:#0d1f33;
  --ink-70:rgba(13,31,51,.78);
  --ink-45:rgba(13,31,51,.66);
  --rule:rgba(13,31,51,.16);
  --rule-strong:rgba(13,31,51,.30);

  --jp:"Helvetica Neue", Helvetica, Arial,
       "Yu Gothic Medium", "游ゴシック Medium", YuGothic,
       "Hiragino Kaku Gothic ProN", "Noto Sans JP", sans-serif;
  --mark:"Helvetica Neue", Helvetica, Arial, sans-serif;
}

@media (prefers-color-scheme: dark){
  :root:not([data-theme="light"]){
    --paper:#0d1f33; --ink:#e8e2d4;
    --ink-70:rgba(232,226,212,.76); --ink-45:rgba(232,226,212,.58);
    --rule:rgba(232,226,212,.17); --rule-strong:rgba(232,226,212,.32);
  }
}
:root[data-theme="dark"]{
  --paper:#0d1f33; --ink:#e8e2d4;
  --ink-70:rgba(232,226,212,.76); --ink-45:rgba(232,226,212,.58);
  --rule:rgba(232,226,212,.17); --rule-strong:rgba(232,226,212,.32);
}
:root[data-theme="light"]{
  --paper:#e8e2d4; --ink:#0d1f33;
  --ink-70:rgba(13,31,51,.78); --ink-45:rgba(13,31,51,.66);
  --rule:rgba(13,31,51,.16); --rule-strong:rgba(13,31,51,.30);
}

/* テーマの既定を上書きする。詳細度を確保するため body に直接当てる */
body,
body.home,
body input, body textarea, body select, body button{
  background:var(--paper);
  color:var(--ink);
  font-family:var(--jp);
  font-size:16px;
  line-height:2.0;
  letter-spacing:.02em;
}
```

### 2-2 数字が和文フォントに落ちないようにする

**これが移植で最も壊れやすい箇所である。**

SWELL のフォント設定は `body` に `font-family` を出力する。そこで和文フォントが先頭に来ると、数字が和文の全角字形で表示され、指示書の指定に反する。

対策は2段構えにする。

1. SWELL のフォント設定で、可能であれば**フォント指定を使わない**か、Helvetica Neue 系を先頭にする（**要確認**：SWELL のフォント選択肢に該当がない場合は 2 のみで対応する）
2. 追加CSSで `--jp` を当て直す。上記 2-1 の `body` セレクタがそれにあたる

適用後、**必ずブラウザで数字を目視確認する。** 「2026年8月13日」「080-9249-3107」「〒839-0254」の3箇所を見て、数字が欧文の字形になっていること。全角の等幅字形になっていたら失敗している。

数字が縦に揃う箇所には併せて指定する。

```css
.record .row, .fcol p, .copyright{
  font-variant-numeric: lining-nums tabular-nums;
}
```

### 2-3 Webフォントを読み込まない

指示書の書体はすべてシステムフォントで完結する。SWELL 側で Google Fonts を読み込む設定になっていたら**切る**（**要確認**：設定項目の所在）。読み込みが残ると表示速度を損ない、かつ意図しない書体に置き換わる。

## 3｜ワードマークを活字で入れる

指示書 §2 のとおり、ロゴは画像ではなく活字で組む。

SWELL のヘッダーロゴ設定は画像アップロードが前提のことが多い（**要確認**）。画像を上げず、**サイトタイトルをテキストで表示させたうえでCSSで整える**方針を取る。

```css
/* ヘッダーのサイトタイトルをワードマークとして組む。
   セレクタは実際の出力に合わせて差し替えること（要確認） */
.l-header .c-headLogo__link,
.l-header .site-title a{
  font-family:var(--mark);
  font-weight:300;
  font-size:26px;
  letter-spacing:.06em;
  line-height:1;
  color:var(--ink);
  text-decoration:none;
}
```

`by YUICHIRO TANAKA` はサイトのキャッチフレーズ欄に入れて表示させる。

```css
.l-header .c-catchphrase,
.l-header .site-description{
  font-family:var(--mark);
  font-weight:300;
  font-size:8.5px;
  letter-spacing:.14em;
  color:var(--ink-45);
  margin-top:6px;
}
```

**注意：** SWELL のヘッダー構造のクラス名は現物を見て確定すること。ブラウザの検証ツールで実際に出力されているクラスを確認してから書く。上記は当たりを付けたものであり、そのままでは効かない可能性がある。

`UO` 記号型（ロックアップ C）はファビコンとSNSアイコンにのみ使う。ヘッダーには使わない。

## 4｜トップページの作り方

固定ページを1枚作り、**指示書どおりのHTMLをそのまま入れる**。

1. 固定ページを新規作成し、タイトルを「ホーム」にする
2. ブロックエディタで「カスタムHTML」ブロックを1つ置き、指示書 §4 の構成でマークアップを流し込む
3. 「設定 > 表示設定 > ホームページの表示」で、この固定ページをホームに指定する
4. SWELL のページ設定で、**タイトル表示をオフ**にする（**要確認**：見出しが二重に出るのを防ぐため）

**SWELL のブロックパーツで組み直さない。** 指示書のレイアウトは型の使い分けが要件になっており、テーマのブロックに置き換えると禁止事項（角丸カード、装飾見出し、アクセントバー）が混入する。

CSS は「外観 > カスタマイズ > 追加CSS」に入れる。分量が多いので、将来的には子テーマの `style.css` に移すほうが管理しやすい。

## 5｜「今日の記録」の実装

毎日書き替える。**店主が1分で書き終えられること**が最優先で、それ以外の要件はすべてこれに劣後する。

### 選択肢の比較

| 案 | 仕組み | 運用の負荷 | 向き不向き |
|---|---|---|---|
| A | カスタム投稿タイプ「記録」＋カスタムフィールド5つ | **低い。** 日付と5項目だけの入力画面になる。過去分が一覧で残る | 一覧・アーカイブが要るならこれ。初期構築の手間は最も大きい |
| B | 通常の投稿にカテゴリ「今日の記録」を付ける | 中。エディタが全機能を出すため、書く場所を探す手間が毎日かかる | 構築は最短。運用が続きにくい |
| C | 再利用ブロック（同期パターン）を1つ作り、毎日上書き | 低い。ただし**履歴が残らない** | 最新1件しか見せないならこれで足りる |

### 推奨

**A を推す。** 理由は3つある。

1. 入力画面を5項目だけに絞れる。装飾機能が目に入らないので、書く行為が1分で終わる
2. 「仕入れませんでした」の日の記録が積み上がる。これはこの店にしか書けない資産で、検索面でも効く
3. 過去の判断を後から見返せる。仕入れの意思決定そのものの記録になる

構築の手間は A が最大だが、それは一度きりである。毎日発生する運用の負荷を下げるほうが優先度が高い。

### A で作る場合のフィールド

| フィールド | 型 | 備考 |
|---|---|---|
| 日付 | 日付 | 投稿日と兼ねてよい |
| 七十二候 | 選択（72項目）または文字列 | 選択にすると入力が速い。日付から自動導出も可能だが、まず手入力で始める |
| 潮 | 選択（大潮・中潮・小潮・長潮・若潮） | |
| 行った市場 | 選択（柳川・佐賀・長崎・福岡・大分・熊本・下関・鳥取・岡山・行かず） | 指示書 §4-7 の9地域に「行かず」を足す |
| 今日の判断 | 選択（仕入れました・仕入れませんでした） | |
| 理由 | テキストエリア | 1〜2文。ここだけが自由記述 |

カスタムフィールドの追加には ACF などのプラグインを使うのが一般的（**要確認**：導入可否と費用）。プラグインを増やしたくない場合は、投稿本文に決まった書式で書く運用でも成立する。その場合は書式を崩さないための見本を管理画面の説明文に置く。

**書かなかった日を埋めない。** 空白も記録である。自動で「記録なし」と出す実装にしない。

## 6｜有明海の映像

`site/media/ariake.mp4` は H.264、9.5MB、縦撮り。

### 実装

```html
<video src="/wp-content/uploads/2026/08/ariake.mp4"
       poster="/wp-content/uploads/2026/08/ariake-sunset.jpg"
       autoplay muted loop playsinline aria-label="有明海"></video>
```

`autoplay` は `muted` が付いていないとモバイルで再生されない。`playsinline` がないと iOS で全画面に飛ぶ。**3つとも必須**である。

### 表示速度への影響

9.5MB はトップページの初期表示としては重い。次の順で対処する。

1. **`preload="none"` を付けない。** 付けると `poster` しか出ず、映像が始まらない
2. モバイルでは映像を出さず `poster` の静止画だけにする。データ量の削減効果が最も大きい

```css
@media (max-width:768px){
  .sea video{display:none}
  .sea .sea-fallback{display:block}
}
@media (min-width:769px){
  .sea .sea-fallback{display:none}
}
```

3. それでも重い場合は、映像を短く切って軽くする。**この環境には ffmpeg がなく、こちらでは変換できない。** 変換が必要なら手元で行うか、変換済みのファイルを支給いただく

### 縦撮りであること

元が縦撮りのため、横長の帯に `object-fit: cover` で入れると上下が大きく切れる。実際の見え方を確認し、切れて困る被写体が入っていれば、静止画に切り替えるか、映像の見せ方（高さ、切り取り位置）を調整する。

**旧資料では「縦撮り・画質の制約により本採用は保留、静止画優先」という判断が過去にあった。** 今回あらためて実機で見て判断すること。

## 7｜メディアの移行

1. `site/images/` の8点と `site/media/ariake.mp4` をメディアライブラリにアップロードする
2. アップロード後のURLを控え、HTML内の相対パス（`images/...` `media/...`）を実URLに置き換える
3. すべての `img` に `alt` を入れる。指示書と浜焼き指示書に記載の文言を使う
4. **写真は1枚につき1ページ。** `mise.jpg` と `nodoguro.jpg` は浜焼きページの持ち分で、トップには置かない

WordPress は画像を自動で複数サイズに変換する。`sumibi.jpg`（946x1267）と `nodoguro.jpg`（913x1260）は元が小さいため、**実寸を超えるサイズで表示されないようにする**。指示書 §5 の上限（560px / 760px）を守る。

## 8｜公開前の確認

指示書 §8 の検証項目に加えて、移植後は次を確認する。

```
 1. 数字が欧文フォントで出ている（日付・電話番号・郵便番号を目視）
 2. SWELL の既定装飾が混入していない（角丸カード、装飾見出し、アクセントバー）
 3. ライト・ダーク両モードで描画し、全文字が読める
 4. 375px で横スクロールが出ない
 5. ワードマークが画像ではなく活字で出ている
 6. 映像がモバイルで再生される、または静止画に切り替わっている
 7. すべての画像に alt がある
 8. 画像が実寸を超えて拡大表示されていない
 9. Google Fonts など外部フォントを読み込んでいない（開発者ツールのネットワークで確認）
10. 構造化データがリッチリザルトテストを通る
11. 表示速度を計測する。LCP 2.5秒未満を目標にする
12. 「一海」「畑地」「有限会社タナカ」「SAKANA TANAKA」が本文・メタ情報のどこにも無い
```

## 9｜確認事項

1. SWELL のライセンスは取得済みか。バージョンはいくつか
2. サーバーとドメインの契約状況。`www.tanakauo.com` は現在どこを向いているか
3. 既存サイトの有無。あるなら既存URLの扱い（リダイレクトの要否）
4. ACF などのプラグインを追加してよいか。費用と管理の許容範囲
5. 子テーマを作るか、追加CSSで済ませるか
6. 映像の変換が必要な場合、手元で行えるか
7. 「今日の記録」は A・B・C のどれで進めるか（推奨は A）
