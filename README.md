どちらに転んでも各指示書の設計（書体・配色・禁止事項・原稿・構成）はそのまま使える。

### 着手前に必ず確認すること

- **§0 の「旧仕様の破棄」を読む。** 金茶 `#B0894E`、明朝の全面使用、写真に重ねる縦書きコピー、薄暮ダークのヒーロー、ロゴのプレート画像、見出しごとの小英字ラベル。これらは過去の指示書に書かれているが**すべて破棄されている**
- **名刺から採るのは、ワードマーク「TANAKA UO」の書体と、住所・連絡先の表記だけ。** 名刺の世界観（地色・文字色・補助色・欧文 Georgia）は移植しない
- **§1 の禁止事項12項目を守る。** 特に 11（一海および畑地優二に一切触れない）と 12（法人名に言及しない）は絶対
- 数字と英字は欧文フォントが受け持つ。和文の全角字形で出してはならない
- **未確定の項目を回答待ちにしない。** `docs/open-questions.md` §3 に全件の扱いが定めてある。**「確認中」「準備中」と書かず、欄ごと出さない**

### 着手を止める項目は無い

確認事項を統合し、35件を決着させ、残り24件にも「確定するまでの扱い」を定めた。
公開の直前に確認するのは3件。**住所の番地**、Googleビジネスプロフィールとの一致、ドメインの向き先。

**営業時間は確定している。** 店頭は金・土・日の 8:00-15:00。月曜から木曜は仕入れと加工にあて、店頭には立たない。
予約でのご注文は受ける。**「定休日」という語を使わない**（`docs/open-questions.md` §2-3-1）。

**住所は書かない。** 事業計画書に 883-1（事業所）と 884（対面営業場所）の2つがあり、客が行くのは 884 のほうである。
番地が確定するまで、本文にも構造化データにも番地を出さない。市までは書いてよい（同 Q26）。

**会員制度と不定期魚BOXに触れない。** どちらも店頭で接客した顧客への案内が前提で、一般公募の制度ではない（同 D32 D33）。
**EC・通販の導線を作らない。** 初年度の店頭外売上は 0 で計画されている（同 D34）。
**事業計画書の数値を1つも書かない。** 売上、客単価、原価率、来店客数、返済計画は金融機関向けの情報である。

### Codexの裁量（使用リミットが近いため。2026-08-19 追記）

**確認や差し戻しに使用量を使わず、決めて進めてよい。**

各指示書に明記されている項目（§1 の禁止事項、書体・配色のトークン、確定原稿の文言、`docs/open-questions.md` §2 の決定事項）は動かさない。
**それ以外の、指示書が数値や型まで指定していない細部**（余白のリズム、罫の太さ、写真の具体的なクロップ量の微調整、レスポンシブの中間ブレークポイント、ホバーの挙動の細かさ等）は、Codex自身のデザインセンスで決めて実装してよい。田中氏の回答を待つ必要はない。

迷ったときは、指示書に明記があればそれに従い、明記が無ければ `docs/open-questions.md` §3 の「確定するまでの扱い」に従う。
それでも決まらない見た目の細部は、§1 の禁止事項に反しない範囲でCodexが決めてよい。

**質問を書き出して回答を待つ、という往復をしない。**
本書と各指示書に「確認事項」「要確認」と書かれた箇所は、**Codexが田中氏に問う項目ではない。**
すべて `docs/open-questions.md` に扱いが定めてあり、回答を待たずに実装できる状態になっている。読み替えて進めること。

**公開の直前に確認する3件（住所の番地、Googleビジネスプロフィールとの一致、ドメインの向き先）も、Codexへの質問ではない。**
田中氏が公開の直前に自分で確認する項目である。実装上の扱いは3件とも確定している。

- 住所 ... 番地を書かない。市までとし、JSON-LD は `address` ごと省く
- ビジネスプロフィール ... サイト側は名刺の表記を正として書く。営業時間は 金・土・日 8:00-15:00
- 向き先 ... 単体HTMLとして向き先に依存しない形にする。ルート配置を前提にせず、相対パスで完結させる

判断した内容と理由は、納品時にコメントか短いメモで添えれば十分である。
